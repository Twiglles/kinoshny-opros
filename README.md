# Киношная — голосование за фильм

Минималистичная страница: фильмы идут списком (постер, название, год, режиссёр, актёры, рейтинги IMDb / Кинопоиск / Rotten Tomatoes), у каждого кнопка «Хочу смотреть». Справа — панель с живой таблицей: кто лидирует, сколько голосов, сколько человек проголосовало. Панель сворачивается и разворачивается кликом по заголовку, на телефоне она живёт внизу экрана.

Каждый может отметить несколько фильмов, повторное нажатие снимает голос. Один браузер = один участник.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | страница |
| `style.css` | оформление |
| `app.js` | логика голосования |
| `films.js` | **список фильмов** — редактируй его |
| `config.js` | **настройки** и подключение Firebase |

## Как поменять фильмы

Проще всего — прямо на странице: в конце списка есть карточка «Добавить фильм». Там можно вписать название, год, длительность, описание, режиссёра, актёров, жанр, рейтинги и загрузить постер (нажать, перетащить файл, вставить из буфера или дать ссылку). Добавленный фильм сразу видят все, а удалить его может только тот, кто добавил (кнопка «Удалить» в его карточке).

Основной список лежит в файле. Открой `films.js`, скопируй блок `{ ... }` одного фильма и поменяй поля. Подсказки по каждому полю — в начале файла.

- Постер: вставь ссылку на картинку в `poster`. Или оставь `poster` пустым и укажи `wiki: "Название_статьи"` с английской Википедии — постер подтянется сам.
- Рейтинги сняты с IMDb, Кинопоиска и Rotten Tomatoes 28.10.2026 и сами не обновляются.
- `id` не меняй, когда голосование уже началось: голоса привязаны к нему.

## Общее голосование: подключить Firebase (≈10 минут, бесплатно)

GitHub Pages умеет только показывать страницы, а голоса нужно где-то хранить. Для этого используем бесплатную базу Firebase Realtime Database: она сразу рассылает изменения всем открытым страницам, поэтому таблица обновляется вживую.

Пока Firebase не подключён, страница работает в **демо-режиме**: голоса сохраняются только в твоём браузере.

1. Зайди на https://console.firebase.google.com → **Add project / Создать проект** (Google Analytics можно выключить).
2. В меню слева: **Build → Realtime Database → Create database**. Регион любой, режим — **Start in locked mode**.
3. Вкладка **Rules** — замени содержимое на это и нажми **Publish**:

   ```json
   {
     "rules": {
       "polls": {
         "$poll": {
           ".read": true,
           "votes": {
             "$film": {
               "$voter": {
                 ".write": true,
                 ".validate": "$voter.length <= 40 && (newData.val() === true || !newData.exists())"
               }
             }
           },
           "films": {
             "$film": {
               ".write": "!data.exists() || !newData.exists()",
               ".validate": "newData.child('title').isString() && newData.child('title').val().length > 0 && newData.child('title').val().length <= 120 && (!newData.child('poster').exists() || newData.child('poster').val().length < 400000)"
             }
           }
         }
       }
     }
   }
   ```

   Так любой может читать результаты, ставить или снимать свой голос и добавлять фильмы (с названием и постером до ~300 КБ). Уже добавленный фильм можно только удалить, а не переписать.
4. Шестерёнка → **Project settings** → внизу **Your apps** → значок `</>` (Web) → придумай имя → **Register app**. Появится объект `firebaseConfig`.
5. Скопируй из него `apiKey`, `authDomain`, `databaseURL`, `projectId`, `appId` в `config.js`. Если `databaseURL` в конфиге нет — возьми адрес со страницы Realtime Database (вида `https://имя-проекта-default-rtdb.europe-west1.firebasedatabase.app`).

`apiKey` у Firebase — не секрет, его можно держать в открытом репозитории: доступ ограничивают правила из шага 3.

## Выложить на GitHub Pages

1. Создай репозиторий на GitHub (например `kinovote`) и загрузи в него все файлы из этой папки (кнопка **Add file → Upload files**).
2. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/ (root)` → **Save**.
3. Через минуту страница будет по адресу `https://<твой-логин>.github.io/kinovote/`. Эту ссылку и кидай друзьям.

## Новое голосование

В `config.js` поменяй `pollId` (например на `"2026-11-01"`) — начнётся чистое голосование, старое останется в базе.
Ограничить количество голосов на человека: `maxVotesPerPerson: 1` (или 2, 3…).

## Выбор дат: «Когда смотрим?»

Вверху обеих страниц есть переключатель **Что смотрим? / Когда смотрим?**

- `dates.html` — страница для всех: календарь на ноябрь 2026 почти на весь экран. Человек нажимает на день и в выпадающем списке прямо в клетке выбирает, во сколько ему удобно («Весь день», «Днём», «С 19:00»…). На компьютере открывается свой список в стиле страницы, на телефоне — системный. Имя можно вписать, можно не вписывать. Всё сохраняется само.
- `dates-stats.html` — **статистика для организаторов**. На главной странице на неё ссылок нет, адрес знаете только вы: `https://<твой-логин>.github.io/kinovote/dates-stats.html`. Там видно, сколько человек ответили, рейтинг дат, тепловой календарь, кто когда свободен в выбранный день, лучшее время начала и выгрузка в CSV (открывается в Excel).

«Лучшее время начала» — это время, с которого больше всего людей смогут досмотреть фильм целиком. Длина фильма задаётся в `config.js` → `dates.movieMinutes`.

Настройки — в `config.js`, блок `dates`: месяц, варианты времени в списке (`slots`), длина фильма. Новый сбор дат с нуля — поменяй `dates.pollId`.

### Правила Firebase для дат

Даты хранятся в той же базе, в ветке `dates`. Без новых правил база не пустит туда запись, и на странице появится «Нет доступа к базе дат». В Firebase → **Realtime Database → Rules** замени всё на это и нажми **Publish** (блок `polls` тот же, что выше, добавился `dates`):

```json
{
  "rules": {
    "polls": {
      "$poll": {
        ".read": true,
        "votes": {
          "$film": {
            "$voter": {
              ".write": true,
              ".validate": "$voter.length <= 40 && (newData.val() === true || !newData.exists())"
            }
          }
        },
        "films": {
          "$film": {
            ".write": "!data.exists() || !newData.exists()",
            ".validate": "newData.child('title').isString() && newData.child('title').val().length > 0 && newData.child('title').val().length <= 120 && (!newData.child('poster').exists() || newData.child('poster').val().length < 400000)"
          }
        }
      }
    },
    "dates": {
      "$poll": {
        ".read": true,
        "answers": {
          "$voter": {
            ".write": "$voter.length <= 40",
            ".validate": "newData.hasChildren(['updatedAt', 'days']) && newData.child('updatedAt').isNumber()",
            "name": { ".validate": "newData.isString() && newData.val().length <= 60" },
            "same": { ".validate": "newData.isBoolean()" },
            "updatedAt": { ".validate": true },
            "days": {
              "$day": {
                ".validate": "$day.matches(/^[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]$/) && newData.child('from').isNumber() && newData.child('to').isNumber() && newData.child('from').val() >= 0 && newData.child('to').val() <= 1440 && newData.child('from').val() < newData.child('to').val()",
                "from": { ".validate": true },
                "to": { ".validate": true },
                "$other": { ".validate": false }
              }
            },
            "$other": { ".validate": false }
          }
        }
      }
    }
  }
}
```

Проверить страницы без базы можно, дописав к адресу `?demo`: тогда ответы хранятся только в браузере (`dates.html?demo` и `dates-stats.html?demo`).

Ограничение то же, что у голосования: человек опознаётся по браузеру, и ответы с именами может прочитать любой, кто знает адрес базы. Для компании друзей этого хватает.

## Посмотреть локально

Открой папку в терминале и запусти:

```bash
python -m http.server 8000
```

Затем зайди на http://localhost:8000.

## Ограничения прототипа

Голосование анонимное, человек опознаётся по браузеру. Если открыть страницу в другом браузере или в режиме инкогнито, можно проголосовать повторно. Для компании друзей этого достаточно. Если понадобится строже, можно добавить вход через Google или ввод имени.
